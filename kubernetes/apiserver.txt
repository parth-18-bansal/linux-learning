1. To see the flags list use the kube-apiserver --help

2. apiserver has 3 endpoints by hitting them we can check whether apiserver is healthy or not
    a. /healthz : overall health check
    b. /livez : check whether apisever is alive and should continue to run or not
    c. /readyz : is apiserver is ready to perform its work or not

we can hit these like this:
curl -k https://127.0.0.1:6443/healthz

and for more detailed output
curl -k https://127.0.0.1:6443/healthz?verbose


** simillary in controller manager we have only /healthz endpoint to check health and we can check
hit it like this
curl -k https://127.0.0.1:10257/healthz

** and scheduler has three endpoints /healthz, /livez, /readyz, and we can check like this:
curl -k https://127.0.0.1:10259/healthz?verbose



3. From worker node: this: curl --cacert ca.crt https://192.168.1.21:6443/version is working without client cert because
__________________________________________________________________________________________________________________________
**
here curl is working without client cert(although mTLS is following), because here api server request the client cert but client cert is optional, 
so by curl we are able to authenticate, so apiserver accepts the request and treat the client's username as "system:anonymous" and group name as
"system:unauthenticated".

this acceptance is control by --anonymous-auth flag, and by default it is true, and if it is true then apiserver accept the anonymous requests at
some basics endpoints like /version, /healthz, /livez, /readyz.

if we set it false then we need client cert also.

here RBAC decides, what a client do, by default, "system:public-info-viewer" cluster-role is attached to "system:unauthenticated", which allow to access
these endpoints: /version, /healthz, /livez, /readyz. i.e why we are able to access this endpoint without client cert.
